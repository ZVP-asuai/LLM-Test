# Архитектура лабораторного журнала

## Источники истины
1. JSON результата — машинно-читаемая запись каждого запуска и основной источник чисел.
2. HTML-отчёт — визуальное представление эксперимента; числа должны совпадать с JSON.
3. Журнал — хронология действий, изменений, ошибок и выводов.
4. Inventory — описание среды с указанием происхождения данных.
5. Dashboard JSON — индекс для панели, не замена исходным результатам.

Если значения расходятся, приоритет имеет JSON и приложенный сырой лог; расхождение исправляется отдельным commit.

## Каталоги
    inventory/       аппаратная и системная инвентаризация
    configs/          конфигурации движков и запусков
    benchmarks/
      schema/         JSON Schema результатов
      prompts/        фиксированные тестовые задания
      results/YYYY/   отдельные записи каждого запуска
    journal/YYYY/     хронология работ
    decisions/        архитектурные решения
    docs/
      index.html      панель лаборатории
      assets/         CSS и JS без внешних CDN
      data/           JSON для панели
      reports/YYYY/   HTML-отчёты запусков
    .github/workflows/ публикация Pages

## Именование
ID: YYYY-MM-DD-model-quant-gpu-test-NNN. Один и тот же ID используется в JSON, HTML и журнале. Повторный запуск получает новый номер. Исторические измерения не перезаписываются.

## Достоверность
Exploratory — одиночный пробный запуск или неполные данные.
Validated — повторяемый тест с полными параметрами, telemetry и проверкой качества.
Failed / Incomplete — ошибка либо недостаточность данных; запись сохраняется.
