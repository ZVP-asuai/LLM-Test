# Методика испытаний

## До запуска
1. Убедиться, что тест выполняется только в CT128.
2. Снять исходные nvidia-smi, процессы, VRAM, температуры, Power Limit и версии драйвера/движка.
3. Зафиксировать точный файл модели, quantization и checksum, если доступна.
4. Сохранить исходный профиль запуска.
5. Проверить отсутствие посторонних процессов на GPU.
6. Присвоить Run ID. Не менять одновременно несколько факторов.

## Обязательные параметры
Дата; модель и файл; quantization; движок и версии; CUDA/runtime; GPU, PCI Bus ID, VBIOS, VRAM, Power Limit; batch/concurrency; KV-cache и dtype; заданный и фактический prompt token count; temperature, sampling, max output, reasoning effort; cold/warm; точный prompt или ID.

## Метрики
- TTFT engine event — время до первого события движка.
- TTFT visible text — время до первого непустого пользовательского текста.
- Prefill tok/s — входные токены / время prefill; записывать число токенов и метод.
- Decode tok/s — выходные токены / чистое время decode.
- End-to-end — полное время запроса.
- VRAM baseline/peak/residual.
- GPU utilization, core, hotspot, memory junction (если датчики доступны), power draw и power limit.
- CPU/RAM, RSS.
- Качество: точность, полнота, русский язык, reasoning, код, function calling, Vision и длинный контекст.

## Контекстная матрица (редакция 2, 2026-11-24)

По указанию владельца обязательная матрица для всех моделей сокращена с шести до трёх точек:
- 32 768 (32K) — контрольная точка;
- 131 072 (128K, около 131–132 тыс.) — начало приоритетной оптимизации;
- 362 000 — буквально указанная верхняя цель, если модель поддерживает её штатно. Значение требует уточнения: ранее верхней целью было 262 144. До уточнения для моделей с нативным пределом 262 144 использовать этот предел, не расширяя окно искусственно.

Контекст означает общий бюджет входных токенов (включая шаблон) и генерации. На предельной длине резервировать место под reasoning и ответ, фиксировать точный фактический вход, выход и общий размер. Не выдавать настроенное окно за проверенное. 8K, 64K и 192K больше не обязательны; дополнительные точки только для локализации проблемы. Исторические измерения сохранять.

## Приоритетная оптимизация длинного контекста

Главная цель — максимальная полезная скорость на 131 072 токенах и выше без деградации качества, с максимальным доступным reasoning и температурным ограничением 70 °C по всем доступным датчикам.

1. Проверить фактические версии Strata, engine components, llama.cpp и других совместимых движков. Сопоставить с официальными релизами и исходным кодом. Не считать установленную версию автоматически последней.
2. Снять baseline на исходном профиле. Исследовать параметры prefill (chunk, batch, microbatch, attention kernels, CPU/GPU allocation, PCIe transfers) и decode (sampling, CUDA graphs, fused kernels, MTP, DFlash, speculative decoding, draft acceptance), если они реализованы и совместимы.
3. Исследовать KV-cache (dtype, quantization, GPU/host placement, reuse), Expert Cache, MoE routing, CPU offload и асинхронные передачи. Изменять факторы отдельно, затем проверять совместное действие лучших вариантов.
4. Найти два ранее применённых успешных патча Qwen3.8 Flash Next по локальной истории, конфигурациям и журналам. Зафиксировать точные diff, исходную ревизию, версию, применимость и результаты. Не считать эффект доказанным на другой модели без повторного A/B теста.
5. Разрешены исследование, установка и сборка новых движков, собственные патчи и экспериментальные сборки исключительно в CT128. Хранить отдельную стабильную сборку, diff, provenance, команды сборки, параметры и откат. Не изменять драйверы, хост, production или системные библиотеки без отдельного согласования.
6. Сравнивать кандидатов по TTFT, prefill, decode, времени до видимого ответа, полному времени и качеству на одинаковом контексте и заданиях. Не сокращать reasoning budget или output budget, не менять sampling и не снижать точность ради искусственного ускорения. Квантование KV/весов и speculative decoding проверять на качество и корректность отдельно.
7. Проверять retrieval в начале, середине и конце, сложные рассуждения, русский язык, код, инструменты и Vision по возможностям модели. Измерять холодный/тёплый режим, cache reuse и параллелизм отдельно. Сравнение победителей — минимум три повторения, медиана; сохранять отрицательные результаты.
8. Приоритет: 128K и верхний поддерживаемый контекст; 32K нужен для контроля регрессий. Не тратить основной бюджет исследований на ускорение коротких запросов.

## Повторяемость
Cold start и warm run отдельно. Для итогового сравнения — не менее трёх одинаковых прогонов и медиана. Отдельно проверять одиночную и параллельную нагрузку. Сравниваемые модели тестировать на одинаковых заданиях.

## Остановка
Прекратить тест при температуре выше целевых 70 °C, CUDA error, OOM, нестабильности питания или риске воздействия на production. Не превышать заводские пределы.

## Публикация
Сохранить JSON по schema, HTML в docs/reports/YYYY/, запись в journal/YYYY/ и обновить docs/data/dashboard.json. Неполные результаты помечать exploratory/incomplete.
