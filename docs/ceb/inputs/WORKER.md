# Протокол адаптера CEB

Скрипт ceb-run.py — внешний таймер и диспетчер. Не является универсальным LLM-клиентом и сам не ограничивает сеть, файловую систему или контекст; это делает доверенный адаптер в отдельной песочнице. Не передавайте модели команду запуска адаптера. Не запускайте с production.

```
python ceb-run.py --prepared prepared --model model.json --output run-001 --strict --qualification --worker /absolute/path/to/trusted-adapter
```

Для диагностики можно убрать --strict и указать --select engineering. Адаптер получает отдельный JSON request на stdin; cwd — каталог отдельной задачи с локальными inputs и artifacts. stdout — один JSON: { "status":"completed", "reason_code":null, "answer":{...}, "evidence":[...], "notes":null, "artifacts":["relative_filename"] }. Адаптер выполняет реальные вызовы LLM в новом контексте, предоставляет только allowlist инструментов и пишет артефакты в artifacts. stdout не содержит служебных логов; stderr — приватный журнал. Завершение процесса включает время инструментов. Для native context адаптер вводит корпус напрямую, фиксирует токенизацию и truncation. Не ищет ответы. Для CAD11 доступен только STEP CAD10. Отсутствующий файл снижает completed до partial; статус и наличие файлов не доказывают инженерную корректность.

Диспетчер фиксирует внешний wall time, exit code, тайм-аут, SHA-256 ответов и файлов, 50 статусов. Проверка содержимого и доверенная телеметрия остаются отдельной стадией. Выход намеренно incomplete, context_isolated=false, network_isolated=false: Python не может подтвердить внешнюю изоляцию. Для зачётного рейтинга требуется адаптер с фактической изоляцией и независимый оценщик. Полные ответы/артефакты сохраняются private; публикуется только ceb-run.json после проверки. Не включайте секреты в model.json.

Для native_context*: supported=false при подтверждённом configured_context ниже целевого размера — это ограничение конфигурации модели, не поломка среды. Preflight признаёт готовность этого теста, runner фиксирует unsupported, продолжая остальные. Оценщик отличает unsupported от отсутствия входных данных.

У blocked/unsupported до старта время null. Если адаптер обнаружил ограничение после реальной попытки, внешний диспетчер сохраняет фактическое время; схема 2.2 допускает это для orchestrated. Карта исходных страниц указывает реальные staged-пути.
