CEB 3.0 — контрольный офлайн-запуск. Набор ceb-100-portable-20261125-r2.
Приложены engineering-inputs.zip и engineering-runner.py (либо комплект CEB-offline-start.zip с этими файлами). Не ищи решения, предыдущие отчёты или эталоны в интернете. Исходный архив не изменять. SHA-256 d7e1172e8f0893d8f9896d48f8501b4d38d8adf0422d6b9df5dde60828540eca, размер 1734045 байт.
Сначала реально проверь среду: python 3, запись/чтение временного файла, запуск дочернего Python, создание/чтение ZIP, хеш входного ZIP, чтение хотя бы одной PDF-страницы или приложенного PNG. Если внешняя оболочка, извлеки из неё исходный ZIP, не путай хеши. Запиши фактические результаты. Без этих возможностей полный зачёт невозможен; не выдавай блокировку среды за инженерную ошибку. Если возможен только текстовый режим, решай доступные задания диагностически, не объявляй полный рейтинг. Если архив и каталог не читаются вообще, сообщи конкретную причину и используй полный резервный промпт, если он приложен.
При наличии Python: python engineering-runner.py --workspace ceb-run start ДО обработки входов; затем проверь SHA-256, распакуй в inputs/, создай run_id и выполни python engineering-runner.py --workspace ceb-run init --catalog inputs/engineering.json --archive engineering-inputs.zip --model "фактическая модель" --run-id "уникальный ID". Условия и критерии в inputs/engineering.json, шаблон в inputs/engineering-report-template.json, инвентарь в inputs/inventory.json. Действует этот регламент, а не старый launch внутри ZIP.
Реши все 100 заданий последовательно. Перед чтением/решением КАЖДОЙ задачи фактически выполни python engineering-runner.py --workspace ceb-run begin N отдельным вызовом. Не готовь ответы заранее вне таймера. После решения, создания обязательных файлов в ceb-run/outputs/, фактической проверки, записи record-N.json по шаблону, выполни python engineering-runner.py --workspace ceb-run end N record-N.json. Таймер пишет измерение сам. Не подменяй время решения временем записи. Если часть работы вне интервала, отметь это. Не выдумывай время или тесты. Промежуточно сохраняй после каждого задания, сообщай короткий прогресс через каждые пять заданий. Не ожидай разрешения продолжать.
Для каждой записи: answer, calculation_steps (исходные значения, метод, подстановка, единицы, результат), sources (файл, локатор, факт), assumptions, checks (ожидаемое и наблюдаемое, статус, доказательство), artifacts (реальные относительные пути), issue (причина и фактические попытки при любом статусе кроме completed). completed — все обязательные результаты и проверки представлены, не гарантирует правильность; partial — часть отсутствует; failed — ошибка; blocked — отсутствует вход/обязательная среда; timeout — лимит; not_run — не начато. Не выдумывай файлы. Ошибка одной задачи не останавливает остальные; невозможность по условиям, доказанная расчётом, является ответом. PLC: Python-модель не является исполнением ST. CAD: геометрия JSON/SVG не STEP. Не запускай код на реальном оборудовании. Локальные тесты запускай с конечным тайм-аутом.
После 100 записей: python engineering-runner.py --workspace ceb-run finalize (с --delivery-log delivery.json при наличии). Затем python engineering-runner.py verify --catalog inputs/engineering.json --zip ceb-run/engineering-outputs.zip --report ceb-run/engineering-report.json. Выдай оба фактических файла, а не ссылки на несуществующие файлы. При лимите сеанса выдай checkpoint и имеющийся архив с тем же run_id, не обещай фоновую работу. Не выставляй себе баллы.
