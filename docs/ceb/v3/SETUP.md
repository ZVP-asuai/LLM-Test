# CEB 3.0 — подготовка и контроль
Новая версия Review: 50 прежних задач сохранены; 50 новых самостоятельных инженерных случаев. core50 и full100 не сравнивать напрямую. Бюджет 120 минут решения + 30 минут подготовки — проектное ограничение, не фактическое время модели. Проверка результатов отдельно. Результаты 2.0 не переносить в 3.0.
1. ZIP из GitHub/зеркала или вложение. Проверить SHA-256 всех входов. Для прежних задач распаковать legacy, использовать исходный контракт и точные внешние документы. Публичный архив не содержит защищённых оригиналов, нормативов, SDK, эталонов. Владелец предоставляет законно полученные копии, если они недоступны. Если нет части входов, фиксировать blocked; не засчитывать как ошибку модели.
2. Изолированный workspace, непривилегированный пользователь. Агент самостоятельно выбирает, пробует, устанавливает нужные средства, фиксирует фактические команды и результаты (без секретов) в приватном журнале; не требуется конкретная библиотека. Отдельное время доставки/настройки/установки. setup-timer.py — необязательный внешний таймер отдельного шага, не песочница. Использовать только доверенные команды в уже изолированном окружении; пакеты из официальных реестров. Отсутствие разрешения установки — ограничение платформы.
3. При решении сеть только №48. Передавать отдельно нужный пакет, для длинного контекста нужен нативный API/токенизатор. Не объявлять файловый поиск нативным контекстом. Сравнение cold setup и warm setup отдельно. Проверка SDK требует лицензии. 
4. run-template.json, status/exploratory; результаты оценивать независимо. Для новых задач acceptance — проверяемые критерии, не ключи; закрытые эталоны и независимая квалификация ещё требуют исполнения и контроля. 

В 3.0 новые испытания требуют независимой проверки не только JSON, но и геометрии и исполнения программ. Например, №81 сопровождается отдельным ортографическим чертежом; №82 использует собственный STEP №81. Внутренние листы сканов не считать внешним оригиналом производителя.
