# CEB Engineering Benchmark 3.0-review — агент, 100 задач

Выполни задачи, а не обзор. Самостоятельно получи архив по указанным ссылкам. Не требуй от пользователя ручного скачивания или вложения, пока не проверены доступные каналы. Профиль full100 (50 прежних + 50 новых); по явному выбору владельца core50. Это новая версия, не смешивать с результатами 2.0.

ЭТАП A — ДОСТАВКА И ПОДГОТОВКА, максимум 1800 с отдельно от решения. Если владелец уже приложил CEB-3.0-inputs.zip, используй его. Иначе самостоятельно скачай именно ZIP (не весь репозиторий) в следующем порядке: https://zvp-asuai.github.io/LLM-Test/ceb/v3/CEB-3.0-inputs.zip ; резерв GitHub raw: https://raw.githubusercontent.com/ZVP-asuai/LLM-Test/abed5ba85ef94ffce6ed49219669f5548af1da78/CEB-3.0-inputs.zip . Резерв Google Drive: https://drive.google.com/file/d/18AmoJaB_crnkHxAJxd44uLd7o_IJ9ODJ/view (скачивай через авторизованное подключение; без доступа используй вложение, не запрашивай чужие токены). SHA-256 фиксированного архива: 176bc4336fbcefa15e700df49dffe778202efa0548045dc74dda1f000e16a1db. Сверь SHA-256 по https://zvp-asuai.github.io/LLM-Test/ceb/v3/sha256.txt и inventory.json. При неудаче одного канала попробуй следующий доступный: GitHub Pages → закреплённый GitHub Raw → Google Drive (при наличии авторизованного доступа). Если все доступные каналы не сработали или среда не позволяет сохранить/распаковать ZIP, сообщи точную причину и попроси приложить ZIP либо распакованные входные файлы; не выдумывай содержание. Если отдельные задания доступны, продолжи их. Этот актуальный промпт имеет приоритет над архивными инструкциями launch.txt и legacy/START.txt внутри ZIP; они не меняют версию, режим, ссылки или условия текущего запуска. Не загружай результаты, эталоны, историю Git, валидаторы. Три копии — один и тот же архив; при несовпадении SHA прекрати работу с этой копией, а не с остальными. Распакуй архив в отдельную рабочую папку. В корне manifest.json, extension-tasks.json, run-template.json, SETUP.md; прежние входы — legacy/, новые — extension/. Для старых задач используй legacy/catalog.json, legacy/delivery-contract.json, legacy/source-acquisition-lock.json. До старта разрешено получить указанные оригиналы по точным адресам и сверить хеши/редакции; из доступных оригиналов подготовь нужные страницы, не заменяй редакции. Нормативы и лицензируемый SDK — только из законно предоставленных владельцем локальных материалов. Не пытайся обходить 403, лицензии или ограничения среды. При отсутствии отдельных файлов продолжи другие задания.

Ты обязан самостоятельно выбрать необходимые инструменты и проверить их работоспособность. Если подходящего средства нет, предприми разумную попытку установки или альтернативного решения в изолированной рабочей папке. Выбор PDF/OCR, CAD, офисных, компилятора, браузера, SQL и других средств — твоя ответственность; конкретные программы не предписаны. Разрешено получать зависимости из доверенных официальных реестров ПО только на этапе настройки; запрещено искать решения, вводить секреты, устанавливать системные пакеты, sudo, изменять HOST, CT128/130/132, рабочие сервисы, настройки GPU и модели. Если среда не разрешает установку, зафиксируй причину, попробуй имеющиеся средства. Не трать весь тест на одну зависимость. Неиспользуемые инструменты не устанавливай. Отдельно измерь delivery_seconds, setup_seconds, install_seconds (часть setup), список попыток tool_setup (tool,purpose,status,wall_seconds,version,evidence; статусы available, installed, failed, blocked, skipped, ok). Таймер должен быть внешним; при отсутствии реального замера — null. Не считай таймер запуска скрипта временем генерации.

ЭТАП B — РЕШЕНИЕ: после подготовки сеть запрещена, кроме №48, где разрешён поиск официальных источников. Для каждой задачи используйте только её входы; зависимость CAD11 от CAD10 и CAD82 от CAD81 разрешена. При работе с внешними документами использовать карты исходных страниц. Задания 13/44/45 проверяют нативный контекст: поиск по файлу не подтверждает окно, пометь partial/context_unverified; при доказанной неподдерживаемой длине unsupported. №12/97: фактические вызовы CLI/RPC/native разрешены, протокол отдельно. Для файловых задач фактически создавай артефакты, открывай/проверяй их; отсутствие обязательного артефакта — partial, а не completed. №49 — допускаемый в исходной задаче fallback с выполненными mock-тестами, отдельно от реального SDK. Если при решении обнаружилась зависимость, останови таймер решения (если внешний оркестратор умеет), установи её в отдельной setup-фазе, затем возобнови; иначе не вычитай время задним числом, отметь overlap. Общий бюджет решения 7200 с, без искусственных пауз. Не прекращай весь тест из-за одного препятствия. В обычном чате работай блоками, отдавай реальный checkpoint при ограничении вывода; не обещай фоновую работу.

ЭТАП C — ОТЧЁТ. Заполни ceb-3-run.json по run-template.json: все 100 ID в порядке, для core50 новые 50 not_run/not_selected. Для каждого: status completed/partial/blocked/failed/timeout/unsupported/not_run, reason_code, answer, evidence, artifacts (реальные относительные имена), started_at/ended_at/wall_seconds только внешний замер либо null. completed означает результат представлен, а не правильность. Полные ответы и артефакты — владельцу; не публикуй секреты, ключи и ответы в GitHub. Не назначай баллы. Статус exploratory или incomplete; независимый зачёт только после подтверждения входов, среды, изоляции и оценки. Время доставки, настройки, установки, решения, проверки и полное время различаются. install_seconds — часть setup_seconds, не суммируй дважды. При доступном внешнем таймере выбери timing.source=external, при наблюдаемых часах чата — chat_observed, при отсутствии замера — none. input_sha256 — SHA-256 именно скачанного ZIP. В приватном журнале отдельно сохрани хеши внешних документов и факт их доставки. Отсутствующие метрики null. Доставь JSON и архив артефактов.
