Выполни CEB 3.0 — 100 инженерных заданий. Это практическая работа, не план и не проверка доступности ссылок. Начни решать доступные задания в этом же ответе/сеансе; не заканчивай одним сообщением о недоступности ZIP.
Доставка: ниже указаны точные ссылки и контрольная сумма фиксированного пакета. Сначала проверь вложенные файлы, затем самостоятельно получи архив всеми РАЗУМНО доступными независимыми способами: GitHub Pages → GitHub Raw → GitHub connector (если подключён, используй чтение файла из ветки ceb-inputs по точному пути, не поиск ответов) → Google Drive (если есть указанное зеркало и авторизация) → Яндекс.Диск (если указано зеркало). В сетевой песочнице ошибка DNS/cURL не означает, что браузер, загрузка файла через коннектор или другой хост недоступны. Различай невозможность открыть ZIP как веб-страницу и невозможность получить его байты. Не повторяй бесконечно один и тот же заведомо недоступный способ; не обходи сетевые ограничения, не запрашивай токены/секреты. Для Яндекс.Диска: открой публичную ссылку, скачай engineering-inputs.zip. Если ссылка ведёт на папку, выбери именно этот файл, не ZIP всей папки. Если веб-страница не отдаёт байты и доступен HTTP-клиент, используй публичный API Яндекс.Диска: запрос resources с параметром public_key=точная публичная ссылка; для файла в папке укажи его path; запрос resources/download с public_key и, при необходимости, path возвращает временный href для скачивания. Не подставляй вместо public_key токен доступа. Не считай HTML-страницу, JSON API или архив всей папки входным ZIP. Если инструмента нет, отметь это, попробуй другой доступный канал. Сверяй SHA-256 каждого полученного ZIP, не используй несовпавшие байты. При недоступности ZIP используй точные отдельные входные файлы из указанной папки ветки ceb-inputs (только каталог, инвентарь, шаблон и материалы заданий). Если байты доступны, сравни их хеши с inventory.json; если нет, честно фиксируй ограничение.
ОБЯЗАТЕЛЬНЫЙ РЕЗЕРВ: в конце этого промпта встроены полные условия 63 самостоятельных заданий. При отсутствии архива и даже при полной недоступности сети начни с №1, затем решай ВСЕ доступные встроенные задания по порядку. Не проси прислать ZIP вместо решения. Просить вложение можно после начала решения, только для оставшихся недоступных материалов. Не объявляй весь тест blocked из-за доставки; указывай блокер по конкретным задачам. При наличии отдельного входного файла выполни и соответствующее задание, даже без полного ZIP. При отсутствии среды исполнения выполняй расчёты и доступную часть задач, предоставляй исходники, но не выдумывай созданные файлы и исполненные тесты. Это диагностический неполный прогон: без подтверждённого ZIP input_sha256=null, полный рейтинг не заявляй.

ПРОТОКОЛ: для каждого задания ответ, исходные значения, формулы/метод, подстановка, результат с единицами, источники, допущения, фактические проверки (ожидаемое и наблюдаемое), выходные файлы и конкретная причина недочёта. Записывай фактические попытки доставки (канал, действие, результат, код ошибки, число байт, проверка SHA); не выдумывай время, вызовы и файлы. completed — ответ представлен, не правильность; partial — доступная часть; failed — ошибка; blocked — обязательный вход или среда отсутствуют; timeout — исчерпан лимит; not_run — не начато. Не выставляй себе баллы.
