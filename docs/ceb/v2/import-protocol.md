# CEB — протокол передачи результатов 2.1

Формат передачи 2.1, набор заданий 2.0-review. Не меняет утверждённые 50 промптов.

1. [Промпт агента](agent-prompt.txt), [шаблон JSON](submission-template.json), [валидатор](import-validator.js).
2. ceb-run.json — публично допустимая сводка без ответов, логов и секретов. Полные ответы и артефакты — закрытый комплект владельца (хеши в сводке). Заполнять все поля, неизвестные значения null. ID, порядок и вес из манифеста. SHA-256 входов рассчитывается оркестратором по согласованному инвентарю, схема проверки формата не доказывает подлинность хеша. manifest_blob_sha — точный Git blob SHA файла docs/ceb/tasks.json.
3. wall_seconds — монотонный замер задания включая инструменты, без независимой проверки; timestamps ISO 8601 с поясом. Верхние timestamps/total_wall_seconds относятся к Standard; qualification_wall_seconds отдельно. Нельзя сравнивать как одинаковый вариант прогоны с разными входными хешами. Токены и параметры неизвестны — null.
4. Допустимые статусы задач: completed, failed, timeout, blocked, not_run, unsupported. reason_code: not_started, missing_input, missing_tool, unsupported_context, dependency_failed, time_limit, runtime_error, invalid_output, policy_block, measurement_unavailable, not_selected, other; null для обычного completed. Для completed нужен answer_sha256. Для submitted нужны 44 выполненных и измеренных задания, хеш входов и время в лимите; иначе incomplete/failed.
5. Импорт на странице сравнения проверяет структуру и сохраняет сводку в localStorage текущего браузера. Это не серверная запись. Открытые ответы/секреты запрещены; не загружать их в публичный GitHub. Повторный run_id не перезаписывается.
6. Для постоянной публикации: владелец запускает workflow CEB: импорт результата (только main) через GitHub Actions, вставляя компактный JSON, либо скачивает ceb-dispatch.json и выполняет `gh workflow run ceb-import.yml --ref main --json < ceb-dispatch.json` из авторизованного терминала с выбранным репозиторием (или добавляет `--repo ZVP-asuai/LLM-Test`). Workflow повторно проверяет данные, добавляет запись в runs.json без перезаписи других записей, коммитит в main и инициирует публикацию Pages. Ограничение входа — 60000 символов. Никаких токенов в HTML/JSON. Для агентов использовать отдельного доверенного издателя после окончания теста, не выдавать агенту права записи. Workflow не запускает модель и не выполняет содержимое ответов.
7. submitted — отчёт принят по формату, НЕ validated. Баллы и критические ошибки присваиваются независимым оценщиком после проверки закрытого комплекта; оценивание и автоматическая публикация verified-оценок пока отдельный этап. В сводных таблицах доступны фактические времена даже без баллов. Рейтинг качества строится только по ранее независимо валидированным прогонам. Текущий набор всё ещё Review.

### Воспроизводимый хеш входов

Перед запуском доверенный оркестратор вычисляет `python3 scripts/ceb-fixture-hash.py <каталог_только_входов> --inventory <путь_вне_каталога>`: относительные POSIX-пути и SHA-256 файлов сортируются по пути, компактный UTF-8 JSON (ключи отсортированы, без завершающего перевода строки) хешируется SHA-256. Манифест закрепляется отдельно Git blob SHA. Входы не должны содержать выходы, логи, эталоны или секреты. Инвентарь хранится в закрытом комплекте, публично передаётся только хеш. При отличающихся данных результаты не объединяются в один рейтинг.

Нажмите название модели в рейтинге для просмотра конфигурации, полного времени Standard/Qualification, 50 строк времени, токенов, инструментов, VRAM и температуры, а также графика десяти самых длительных заданий.
