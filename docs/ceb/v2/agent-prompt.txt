Резервный длинный промпт НЕ является полным комплектом. Владелец заранее прикладывает CEB-offline-inputs.zip или распакованные файлы и подготовленные оригиналы. Не пытайся повторно скачивать недоступный ZIP. Ты — испытуемая модель. Выполни задания, а не обзор или диагностику запуска. Этот промпт предназначен для нового временного чата ChatGPT, Claude, Gemini, DeepSeek и других моделей без внешнего оркестратора. Никаких изменений компьютеров, CT128, HOST, production, GitHub. Не выдавай себе баллы.

ВАЖНО: отсутствие отдельного контекста, таймера, GPU-телеметрии, хеша входов, SDK или части документов НЕ является основанием отказаться от всех задач. В обычном чате они необязательны. Выполняй всё, что доступно. Начни с реального решения №1. Нельзя завершить работу отчётом с 0 ответов, если текстовые задания доступны. Пропусти только конкретную недоступную задачу и сразу переходи к следующей. Если часть результата возможна — сделай её (partial) и укажи, чего не хватает. Для CAD без CAD-инструмента предоставь исходник/техническое описание, но не заявляй о создании STEP. Для схем без изображения не выдумывай связи. Для длинного контекста анализ через чтение файла — только partial, не нативный тест длины. Если нет инструмента для SDK/офиса, делай доступную часть.

Внешние PDF получай только по точным ссылкам каталога до решения или из вложений; при 403 используй указанное зеркало той же редакции, иначе blocked/source_unverified. Общий ориентир Standard (№1–44) 120 минут при возможности измерить; не жди и не обещай фоновую работу. №45–50 отдельно. Если лимит одного ответа мешает, выдай РЕАЛЬНЫЕ готовые решения/файл checkpoint, перечисли следующий блок и попроси написать «Продолжай CEB»; в следующем сообщении продолжи с него. Не ограничивайся планом. Если можно создать файл, записывай решения в JSON непосредственно в ходе выполнения. Если инструмент создания файлов отсутствует, верни корректный JSON в блоке кода. Отсутствующие задания можно не включать в промежуточный JSON: импортёр восстановит их как not_run. В финальном отчёте стремись к 50 строкам. При продолжении сохраняй тот же run_id, выдай один объединённый итоговый отчёт (промежуточные не публикуй).

ФОРМАТ: один компактный файл ceb-chat-result.json, не старый строгий шаблон на 30 КБ. Объект:
{"format":"ceb-chat-result-1","suite_version":"2.0-review","manifest_blob_sha":"f074e90e50a6aa4d5deb54de49fa8a333adf099f","run_id":null,"variant_id":"ceb-2.0-public-preview","model":{"name":"фактическое имя","developer":null,"agent":null,"reasoning_effort":null},"tasks":[{"id":"engineering","status":"completed","reason_code":null,"answer":{},"evidence":["краткая проверяемая формула/источник"],"notes":null,"artifacts":[]}]}
Это пример структуры, НЕ ответ на engineering. Для completed/partial answer должен содержать реальный ответ/код/результат, не пустой объект. evidence — проверяемые формулы, источники, наблюдения (не скрытые рассуждения). Для blocked/not_run/unsupported answer=null. Статусы: completed — необходимый результат представлен; partial — содержательная часть представлена, недостающий файл/проверка указаны; blocked — невозможно начать из-за конкретного входа/инструмента; failed — попытка не удалась; timeout — реальный тайм-аут; unsupported — отсутствие возможности; not_run — ещё не выполнялось. reason_code: not_started, missing_input, missing_tool, unsupported_context, dependency_failed, time_limit, runtime_error, invalid_output, policy_block, measurement_unavailable, not_selected, other, missing_artifact, context_unverified, source_unverified, output_limit, missing_sdk, missing_normative. Для completed null допустим. Для partial и остальных укажи точную причину. Если ничего не известно, null, не выдумывай. Артефакты — массив имён реально созданных файлов. Если есть настоящий внешний замер задачи, можно добавить started_at, ended_at, wall_seconds в строку; иначе не добавляй их. Не измеряй время генерации таймером запуска скрипта. Не включай приватные данные/секреты. variant_id уже задан, run_id может остаться null (сайт назначит UUID). Не вычисляй баллы или хеши из воздуха. Chat-отчёт автоматически получает exploratory или incomplete и не попадает в зачётный рейтинг скорости/качества. JSON импортируется на https://zvp-asuai.github.io/LLM-Test/ceb/v2/index.html#import ; полные ответы остаются локально, в GitHub можно передать только сводку.
