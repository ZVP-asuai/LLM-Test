# CEB 2.0 — ОРКЕСТРАТОР / официальный измеряемый прогон
Этот промпт предназначен только управляющему агенту с отдельными API-вызовами, а не обычному чату. Если таких возможностей нет, используй chat-start.txt; не создавай пустой отчёт вместо решения.

Ты — испытуемый инженерный агент. Твоя задача: выполнить официальный комплект CEB, а не написать обзор теста. Репозиторий: https://github.com/ZVP-asuai/LLM-Test . Разрешён единственный этап подготовки: получить ТОЛЬКО манифест https://raw.githubusercontent.com/ZVP-asuai/LLM-Test/main/docs/ceb/tasks.json , шаблон https://raw.githubusercontent.com/ZVP-asuai/LLM-Test/main/docs/ceb/v2/submission-template.json и утилиту хеширования https://raw.githubusercontent.com/ZVP-asuai/LLM-Test/main/scripts/ceb-fixture-hash.py , а также разрешённые входные файлы из манифеста/предоставленного владельцем комплекта. Входы: https://zvp-asuai.github.io/LLM-Test/ceb/inputs/input-pack.zip ; точные внешние PDF и резервные URL: https://raw.githubusercontent.com/ZVP-asuai/LLM-Test/main/docs/ceb/inputs/catalog.json . Входы должны быть локально закреплены до решения. Недостающие материалы блокируют только конкретное задание. Проверь версию 2.0-review и 50 ID; закрепи точный Git blob SHA манифеста и SHA-256 входного комплекта (по каталогу неизменяемых входов с помощью официального scripts/ceb-fixture-hash.py до запуска; не включай выходы, эталоны и логи; не подставляй случайный хеш). Если входов нет, отмечай blocked, не придумывай их. Не читай v2/runs.json (учебный inputs/fixtures/runs.json для html_build разрешён), reference-audit.json, ответы, результаты других моделей, историю коммитов, валидаторы, закрытые файлы или другие страницы сайта. Получение манифеста и разрешённых материалов до начала теста не является разрешением поиска ответов.

Выполни 44 основных задания последовательно в порядке tasks[].number, максимум 7200 секунд суммарно; затем отдельно попытайся выполнить 6 дополнительных. Не жди искусственно. Каждый промпт передавай без смысловых изменений в новый контекст (кроме явно заданных зависимостей, например CAD → точки подключения). Обеспечь сетевой запрет на этапе решения: 49 задач только локальные входы и allowlist, лишь live_search разрешает официальные источники. Инструменты модели не имеют доступа к эталонам, предыдущим ответам, секретам и учётным данным публикации. Не изменяй HOST, CT130, CT132, рабочие системы, модели и настройки движка без отдельного разрешения. Не запускай команды на production. CT128 — только разрешённая тестовая среда; температурный предел 70 °C. При отсутствии инструмента зафиксируй blocked/unsupported и продолжи.

Перед каждым запросом внешний оркестратор записывает started_at (ISO 8601 с часовым поясом), после последнего готового ответа/файла — ended_at и wall_seconds монотонным таймером. Включай время инструментов в wall_seconds, не включай последующее оценивание. Записывай TTFT, visible TTFT, prefill/decode tok/s, фактические токены, reasoning tokens, число инструментов, их время, пиковую VRAM в байтах, температуру °C, энергию Wh — только при наличии реальной телеметрии. Если измерения нет, null; не оценивай время по длине текста. Укажи фактические имя/разработчика модели, параметры, квантование весов и KV, движок/версию, агент/версию, reasoning effort, context, GPU, driver, seed, temperature, top_p, max_output_tokens. Не выдумывай неизвестные параметры.

Сохраняй полные ответы каждого задания, evidence, фактический вывод инструмента и артефакты (STEP, CSV, код, HTML и т.д.) в отдельном ЗАКРЫТОМ комплекте. Структура ceb-answers.json: {"run_id":"...","suite_version":"2.0-review","tasks":[{"id":"engineering","answer":{...},"evidence":[...],"artifacts":[{"name":"...","sha256":"...","bytes":123}],"tool_log":[...]}]}. Каждый ответ сериализуй в отдельный UTF-8 JSON файл и запиши SHA-256 его фактических байтов в answer_sha256. SHA-256 полного ceb-answers.json запиши в answers_sha256; храни исходные файлы рядом. Не включай секреты, персональные данные, скрытые рассуждения или токены доступа.

Главный итог — ceb-run.json, точно по submission-template.json, все 50 записей с теми же ID и порядком, без дополнительных полей. run_id уникальный, variant_id по умолчанию ceb-2.0-public-preview; другой вариант только при согласовании. schema_version=2.2, execution_mode=orchestrated, telemetry_source=external_orchestrator, context_isolated/network_isolated=true только если реально обеспечены. started_at/ended_at/total_wall_seconds — только Standard, qualification_wall_seconds — отдельно. Для задач status: completed, partial, failed, timeout, blocked, not_run, unsupported; reason_code из перечня: not_started, missing_input, missing_tool, unsupported_context, dependency_failed, time_limit, runtime_error, invalid_output, policy_block, measurement_unavailable, not_selected, other, missing_artifact, context_unverified, source_unverified, output_limit, missing_sdk, missing_normative; если выполнено без измерения — measurement_unavailable. После лимита оставшиеся задачи not_run/time_limit. Не пропускай строки. status всего прогона submitted только если все 44 основных задания завершены, измерены, входы закреплены и Standard <=7200 с; иначе incomplete либо failed. Не назначай баллы, не ставь validated и не заявляй правильность. Это работа независимого оценщика. Не пытайся самостоятельно коммитить ответы или публиковать результаты. Верни владельцу ceb-run.json для импорта и закрытый комплект ответов/артефактов для проверки. Если у тебя нет внешнего таймера, пиши null, а не вымышленные цифры.

Для partial сохраняй содержательный результат с хешем, указывай причину, но не считай за completed. Не прекращай весь прогон из-за недостающего инструмента; решай остальные задачи. Нативный длинный контекст требует подтверждения фактического числа токенов; чтение preview через инструмент — partial/context_unverified. submitted означает приём формата, не квалификацию, пока эталоны и входы не закрыты.


УТОЧНЕНИЯ К ЗАДАНИЯМ (не меняют исходные данные):

- context32: Без подтверждённой нативной загрузки и подсчёта токенов результаты анализа файла — только partial/context_unverified.
- context128: Без подтверждённой нативной загрузки и подсчёта токенов результаты анализа файла — только partial/context_unverified.

- office: При отсутствии средства создания/проверки файлов решите доступную содержательную часть и пометьте partial.
- standards: Не выдумывайте пункты нормативов; неподтверждённые ссылки не считаются доказательством.
- eplan_api: Без реального SDK отделяйте исходник/проектное решение от фактически проверенного исполнения: partial.
